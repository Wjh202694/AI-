# 网页替身（Subagent 路由）

## 功能定位
「重型子任务外包器」+「浏览器执行器」。核心思路源自 Subagents：把又重又吃推理的独立子任务，委派给具备联网搜索能力的子代理，只回收**精炼结论**，避免主会话被长推理拖垮。

## 机制：两种模式（先判定再选）
- **模式 A — 宿主内子代理（首选）**：在主会话内派生独立子代理承载子任务。
  - WorkBuddy：调用 Agent 工具（general-purpose）。**子代理是否自带联网搜索能力需实测确认**；若不带，显式授予 WebSearch/WebFetch 工具或退回模式 B。
  - ZCode（已实测 2026-09-20）：Agent 工具（general-purpose/Explore），子代理自带 WebSearch/WebFetch，查证任务返回合规结论包。
  - 适用：需要实时信息、长文分析、方案对比。
- **模式 B — 外部网页大模型**：仅当宿主**无可用联网搜索能力**时，且须经用户授权并指定站点。
  1. 选站：由**用户指定或经授权后选用**带联网搜索的网页大模型（不写死站名以免过时）。
  2. 投递：把子任务目标 + 输出模板（见附录 A）一次性粘贴。
  3. 提取：优先用页面**复制按钮 / 结构化 DOM** 取回答（而非整页抓取）；按模板抽取结论。遇到登录墙/付费墙，停止并交还用户，不尝试绕过。
  4. 风险：跨网页粘贴含敏感信息需用户授权；结论需二次核验。

## 何时委派（触发条件）
满足任一项即视为「重型独立子任务」，自动转包：
- 资料搜索 / 联网调研（需最新信息）
- 长文本分析（论文、报告、日志摘要）
- 方案对比（多选项打分、权衡）
- 任何「吃推理、可隔离、结果可浓缩」的子任务

## 工作流（委派模式）
1. 识别：在主任务中切出可独立、需搜索/重推理的子任务。
2. 派单：用模式 A（优先）或模式 B 承载，附清晰目标 + 输出模板；**同时派发 ≤3 个互不依赖的子任务**（软上限）。
3. 回收：只取精炼结论包（≤500 字，固定模板），不搬运原始冗长过程。
4. 整合：把结论嵌回主任务上下文；重复出现的同类子任务**先查持久化结论库**，命中即复用。

## 并行与复用策略
- 多个互不依赖的重型子任务：并行派发，软上限 **同时 ≤3 个子代理**。
- 有依赖关系：串行，前者结论包作为后者输入。
- 复用：同会话/跨会话相同问题，先查 `research/YYYY-MM-DD-<slug>.md`（见附录 B）；命中标注「复用 <日期> 结论」，不再派发。

## 浏览器执行（补充能力）
需真实网页操作时用 agent-browser：open → snapshot -i（取 @refs）→ 按 ref 交互 → 重新 snapshot。
常见：登录态保持（state save/load）、表单填写、数据采集、截图/PDF、把视频成品发布到 B站/CMS。
- **验证码兜底**：遇验证码、短信验证、风控拦截，**立即停止并交还用户**，不假装全自动、不重试绕过。
- **state 文件安全**：登录态 `state save` 文件含敏感凭证，存放于工作区外的隔离目录（如 `~/.workbuddy/.agent-browser-states/`），**不入库、不随项目提交、不外传**。

## 输入
- 重型子任务描述 + 期望输出（结论要点 / 来源 / 格式）
- 浏览器任务：目标 URL、操作指令、凭证（环境变量，禁止硬编码）

## 输出
- 精炼结论包（≤500 字，见附录 A）
- 浏览器任务：结果数据 / 截图 / PDF / 录屏 / 状态报告

## 关键规则
- 子任务必须「可隔离、可浓缩」；否则留在主会话。
- 联网结论须标注来源，区分「已核实」与「模型推断」。
- 浏览器操作严守授权边界，敏感凭证走环境变量，不绕过合法鉴权。
- Refs 在导航后会变化，每次导航后必须重新 snapshot 再交互。

## 环境依赖 + 降级
- 依赖（模式 A）：Agent 工具；联网搜索/网页抓取能力（WorkBuddy 内置，需实测子代理是否已带）。
- 依赖（浏览器）：`agent-browser` CLI（`npm i -g agent-browser`；本机实测装完即用，无需额外 install；首次运行 daemon 冷启动较慢，open 卡住时 stop 后重试一次）。
- 降级：
  - 无 Agent 工具 → 切模式 B，或仅在主会话内以「联网搜索 + 手动提炼」处理，并提示结论未经验证。
  - 无 `agent-browser` → 浏览器类任务停止并报告缺口，交付「操作步骤清单」供用户手动执行。

## 验收标准
- 结论包 ≤500 字且 5 字段（结论要点/证据/来源+日期/置信度/未决问题）齐全。
- 每条结论带来源；区分已核实与推断。
- 浏览器任务：遇验证码已停止交还；state 文件未入库。
- 委派任务：同时并行子代理 ≤3。
- 跨会话复用结论已先查 research/ 库。

## 协作（给主会话的指令）
- 交接上下文建议主会话调用 skill: conversation-handoff（对话交接）。
- 视频成品发布 B站、UI 产出真实浏览器验证，分别由主会话调用 skill: video-bilibili-shorts（B站短视频制作）/ skill: ui-award-design（获奖级 UI 设计）处理。

## 附录 A：子任务结论包（硬约束 ≤500 字）

> 子代理回传必须严格套用此模板，超出字数压缩至 500 字内；来源须区分「已核实」与「模型推断」。

- **结论要点**: <3–5 条，直接回答主任务所需，每条一行>
- **证据**: <支撑结论的关键事实/数据，附上下文，不堆砌过程>
- **来源 + 信息日期**: <出处链接或文档名 + 抓取/发布日期；标注「已核实」或「推断」>
- **置信度**: 高 / 中 / 低（并说明依据）
- **未决问题**: <仍需主任务决策或进一步调研的点>

### 使用约定
- 主会话只消费「结论要点 + 证据 + 来源」，丢弃子代理原始长输出。
- 同会话/跨会话重复同类问题：先查 research/ 库，命中即复用，标注「复用 <日期> 结论」。
- 多子任务并行时，每个结论包独立成块，便于合并。

## 附录 B：结论持久化（跨会话复用）
- 子代理返回的有价值结论，落盘为 `research/YYYY-MM-DD-<slug>.md`（slug 取主题短名，与 handoff/ 同构）。
- 文件含：子任务问题 + 结论要点 + 来源 + 信息日期 + 置信度。
- 后续同类子任务派发前，先扫 `research/` 最新相关文件；命中则复用，不再派发，省 token。
- `research/` 与 `handoff/` 同为工作区子目录；不入库、不含敏感信息。
